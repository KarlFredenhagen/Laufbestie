# Laufplan Generator (Laufbestie)

Upload your run history (GPX/TCX/FIT/CSV), answer a short wizard, and get a personalized
running plan generated by Gemini. Runs entirely as a static site — **no server, no backend,
no database** — hosted for free on GitHub Pages. The app's UI and the plans/answers Gemini
generates are in German; this README stays in English for maintainability.

Also works as an installable PWA — see [Installing on your phone](#installing-on-your-phone).

## Stack

- **React + Vite**, built as a static site. Nothing runs server-side.
- **Gemini API**, called directly from the browser (`generativelanguage.googleapis.com`).
- **Your browser's `localStorage`** holds everything: activities, preferences, plans,
  calendar events, feedback, and the Gemini key itself. Nothing is synced anywhere —
  each browser/device has its own independent data. There is no login, because there is
  no server to check a password against.

## Project layout

```
frontend/   The entire app — React PWA, file parsers, aggregation logic, Gemini client
```

(There used to be a separate Express+SQLite backend and a companion `laufbestie-server`
deploy repo; both are obsolete now that everything runs client-side.)

## 1. Get a Gemini API key

1. Go to [aistudio.google.com/apikey](https://aistudio.google.com/apikey) and sign in with
   a Google account.
2. Click **Create API key**, copy it.
3. Free tier, no credit card required. You'll paste this into the app's setup screen the
   first time you open it — it's stored only in that browser's `localStorage`, never sent
   anywhere except directly to Google's API.

## 2. Run it locally

```bash
npm run install:all
npm run dev
```

Opens at **https://localhost:5173**. The dev server uses a self-signed HTTPS certificate
(via `@vitejs/plugin-basic-ssl`), which your browser will warn about the first time
("connection is not private") — click through it (e.g. "Advanced" → "Proceed"). This is
required so the app can be installed as a PWA; browsers only allow PWA install on secure
origins.

## 3. Deploy to GitHub Pages (free hosting)

A workflow (`.github/workflows/deploy.yml`) already builds and deploys automatically on
every push to `master`. One-time setup:

1. **The repo must be public** for GitHub Pages to be free (a private repo needs GitHub
   Pro/Enterprise to publish Pages). If you'd rather keep the source private, host it
   somewhere else that supports private static sites (Netlify, Vercel, Cloudflare Pages
   all have free tiers that work with private repos).
2. In the repo's **Settings → Pages**, set **Source** to "GitHub Actions".
3. Push to `master` — the workflow builds the Vite app and publishes `frontend/dist`.
4. Your app is live at `https://<your-username>.github.io/Laufbestie/`.

If you rename the repo, update `GITHUB_PAGES_REPO` in `frontend/vite.config.ts` to match —
it's used to prefix asset URLs correctly for a GitHub Pages project site.

## Security note: the API key lives in the browser

Because there's no server, there's nowhere to hide the Gemini key — it's used directly from
client-side JavaScript. Anyone who opens your deployed page and inspects the browser's
dev tools / network requests could extract *their own* entered key (not yours — each visitor
enters and stores their own key locally, it's never bundled into the built code or sent to
anyone but Google). This is the same tradeoff a sibling project (essensbestie) already makes.
To reduce misuse risk further, you can restrict your key in
[Google Cloud Console](https://console.cloud.google.com/apis/credentials) to only accept
requests from your GitHub Pages domain (HTTP referrer restriction) — not bulletproof, but
cuts down on casual abuse.

## Export your run data

**Easiest: Garmin Connect CSV export.** Go to your Activities list on
[connect.garmin.com](https://connect.garmin.com) and click **Export CSV** — this downloads one
file with a row per activity (distance, time, heart rate, elevation gain, etc.), no per-activity
digging required. Drop that one CSV file onto the upload page.

Other options, if you want full GPS-track detail instead of just summary stats:

- **Per-activity export**: open an activity on Garmin Connect, click the gear/settings icon, and
  choose **Export to GPX/TCX/FIT**. Repeat per run — more detail, but slower for many runs.
- **Bulk export**: Garmin account settings → **Data Management** → **Export Your Data**. Garmin
  emails a zip within a day or two, including per-activity FIT files.

Strava exports (Settings → My Account → Download or Bulk Export) work the same way and produce
GPX files per activity.

You can drop dozens of files onto the upload page at once, mixing formats freely; non-running
activities (rides, swims, walks) are automatically skipped, re-uploading a file you've already
imported is a no-op, and everything is parsed **in your browser** — files never leave your
device except the final aggregated numbers that go to Gemini when you generate a plan.

## Installing on your phone

Once it's deployed to GitHub Pages (or running locally over HTTPS):

1. Open the URL in your phone's browser.
2. Use the browser's "Add to Home Screen" / install option (Android Chrome shows an install
   banner or menu item; iOS Safari: Share → "Zum Home-Bildschirm"). The app opens full-screen
   with its own icon, no browser address bar.
3. Enter your Gemini API key once on that device — it's stored locally per-browser, so you'll
   do this separately on your phone and your computer, and their data won't be synced (see
   [Stack](#stack) above).

## Ask the Coach

The "Frag den Coach" tab answers free-form running questions directly — no upload or saved
preferences required. If you do have training data and preferences saved, the coach uses them
as context automatically; otherwise it just answers from general running knowledge.

## Calendar & adjusting a plan

The "Kalender" tab lets you note upcoming events (races, travel, anything that affects
training) — both plan generation and plan adaptation send upcoming events to Gemini as
context automatically.

In the "Plan" tab, once a plan exists you get three actions:
- **Plan anpassen** — adjusts the current plan in place (same weeks, revised going forward)
  given fresh training data, calendar events, and an optional free-text note about what
  changed (illness, injury, a moved race date, more/less available time).
- **Neuen Plan erstellen** — starts over from the preferences wizard.
- **Plan löschen** — clears the current plan back to the empty state.

## Personal bests, race predictions, and feedback

- **Persönliche Bestzeiten** (Dashboard): best known time near each standard distance
  (5K/10K/half/marathon), computed from uploaded activities within ±5% of the target distance
  (there's no GPS-split data to interpolate an exact-distance time from). You can also enter
  bests manually in the plan wizard — useful if you haven't uploaded anything yet; a manual
  entry always takes priority over an activity-derived one for the same distance.
- **Rennzeit-Prognose**: projected finish times extrapolated from your single best recent
  effort (last 90 days) using Riegel's race-time-prediction formula
  (`T2 = T1 * (D2/D1)^1.06`), a well-established public formula — pure math, not a Gemini call.
- **Gefühls-Check-in**: tap 😞/😐/😄 on any non-rest day in the plan to log how it felt. Recent
  check-ins are sent to Gemini as context when you click "Plan anpassen".
- **Krafttraining**: the plan can include a `strength` day type (short strength/mobility
  session) alongside the running day types, when it fits the schedule.

## How it works

1. **Upload** — GPX/TCX are parsed as XML (`fast-xml-parser`), FIT is parsed as binary
   (`fit-file-parser`), CSV (Garmin's activity-list export) is parsed with `csv-parse` — all
   running in the browser via the File API. Each file is normalized into a common shape (date,
   distance, duration, pace, heart rate, elevation) and deduplicated by date+distance+duration
   before being saved to `localStorage`.
2. **Aggregation** — before anything is sent to Gemini, the stored activities are reduced to a
   compact summary (weekly mileage, pace trend, longest run, frequency, elevation trend, a
   recent hard-effort proxy). All the arithmetic happens locally in code — Gemini never sees
   raw per-run data.
3. **Plan generation** — the aggregated summary + your preferences are sent to Gemini
   (`gemini-2.5-flash` by default) using structured output (`responseSchema`) so the response
   is guaranteed valid JSON matching the plan schema, in German, with German weekday names. The
   resulting plan is cached in `localStorage` and only regenerated when you ask for it.
4. **Model resilience** — if the configured model ever returns 404 for your key (e.g. a model
   name goes stale), the app automatically looks up which models your key can actually use and
   switches to one, the same pattern used in a sibling project (essensbestie).

## Notes

- Every format-specific parser and the whole aggregation layer used to live in a Node.js
  backend; they were ported essentially unchanged into `frontend/src/parsers/` and
  `frontend/src/aggregate.ts` — the algorithms don't care whether they're called from Express
  or from a browser event handler.
- `csv-parse` and `fit-file-parser` both reference Node's global `Buffer`, which doesn't exist
  in a browser. `vite-plugin-node-polyfills` (scoped to just `buffer`) patches that in — it's
  the standard fix for this class of issue, not a hack specific to this app.
- Preferences and the "day" field in generated plans use German weekday names (Montag..Sonntag)
  as their canonical values throughout — not just as a display label — since this is a
  single-language personal tool.
- PWA icons (`frontend/public/icons/`) are generated by `frontend/scripts/make-icons.cjs`, a
  small script that hand-encodes PNGs via Node's built-in `zlib` — no image library dependency.
  Re-run it with `node scripts/make-icons.cjs` if you want to tweak the icon design.
