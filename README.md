# Laufplan Generator (Running Plan Generator)

Upload your run history (GPX/TCX/FIT/CSV), set your training preferences, and get a
personalized running plan generated by Claude. The app's UI and the plans/answers Claude
generates are in German; this README stays in English for maintainability.

Also works as an installable PWA — see [Installing on your phone](#installing-on-your-phone).

## Stack

- **Backend**: Node.js + Express + TypeScript, SQLite (via Node's built-in `node:sqlite`)
- **Frontend**: React + Vite PWA, plain CSS, Recharts for the mileage chart
- Email+password login, cookie-based sessions. No public sign-up — accounts are created
  manually (see [Accounts](#accounts)). Each account's activities/preferences/plans/events
  are fully separate.

## Project layout

```
backend/    Express API, file parsing, SQLite storage, Claude integration
frontend/   React PWA (upload, dashboard, preferences, plan view, ask-the-coach)
```

## 1. Get an Anthropic API key

1. Go to [console.anthropic.com](https://console.anthropic.com) and sign in / create an account.
2. Navigate to **API Keys** and create a new key.
3. Copy it — you'll paste it into `backend/.env` below.

## 2. Set up and run

```bash
npm run install:all
```

Then create your backend env file:

```bash
cp backend/.env.example backend/.env
```

Edit `backend/.env` and paste in your API key:

```
ANTHROPIC_API_KEY=sk-ant-...
CLAUDE_MODEL=claude-haiku-4-5-20251001
PORT=3001
```

Run both servers together:

```bash
npm run dev
```

- Backend: http://localhost:3001
- Frontend: **https://localhost:5173** (note: HTTPS — see below)

The frontend dev server uses a self-signed HTTPS certificate (via `@vitejs/plugin-basic-ssl`),
which your browser will warn about the first time ("connection is not private" /
"not secure") — click through it (e.g. "Advanced" → "Proceed"). This is required so the app
can be installed as a PWA; browsers only allow PWA install and offline support on secure
origins. The Vite dev server proxies `/api/*` requests to the backend, so just use the
frontend URL for everything.

## 3. Accounts

There's no sign-up page on purpose — create your account from the command line:

```bash
cd backend
npm run create-user -- you@example.com "a good password"
```

Run it again with different credentials to add another account (e.g. for a partner). Log in
at the app's URL with that email/password; sessions last 30 days via an httpOnly cookie.

## 4. Export your run data

**Easiest: Garmin Connect CSV export.** Go to your Activities list on
[connect.garmin.com](https://connect.garmin.com) and click **Export CSV** — this downloads one
file with a row per activity (distance, time, heart rate, elevation gain, etc.), no per-activity
digging required. Drop that one CSV file onto the upload page.

Other options, if you want full GPS-track detail instead of just summary stats:

- **Per-activity export**: open an activity on Garmin Connect, click the gear/settings icon, and
  choose **Export to GPX/TCX/FIT**. Repeat per run — more detail, but slower for many runs.
- **Bulk export**: Garmin account settings → **Data Management** → **Export Your Data**. Garmin
  emails a zip within a day or two, including per-activity FIT files.

Strava exports (Settings → My Account → Download or Bulk Export) work the same way and produce
GPX files per activity.

You can drop dozens of files onto the upload page at once, mixing formats freely; non-running
activities (rides, swims, walks) are automatically skipped, and re-uploading a file you've
already imported is a no-op.

## Installing on your phone

Once `npm run dev` is running:

1. Make sure your phone is on the same WiFi as your computer.
2. Find your computer's LAN address — the frontend terminal output prints it, e.g.
   `https://192.168.0.145:5173`.
3. Open that address in your phone's browser. Accept the self-signed-certificate warning
   (this is expected — it's your own dev server, not a real public site).
4. Use your browser's "Add to Home Screen" / install option (Android Chrome shows an install
   banner or menu item; iOS Safari: Share → "Zum Home-Bildschirm"). The app opens full-screen
   with its own icon, no browser address bar.

The backend only needs to be reachable from your computer, not your phone — the frontend's own
server proxies API calls to it, so the backend can stay on `localhost`.

For anything beyond local testing (e.g. a real app-store listing), you'd want
[Capacitor](https://capacitorjs.com/) to wrap this same web app in a native shell — not set up
here, since it isn't needed for personal use on your own WiFi.

## Ask the Coach

The "Frag den Coach" tab answers free-form running questions directly — no upload or saved
preferences required. If you do have training data and preferences saved, the coach uses them
as context automatically; otherwise it just answers from general running knowledge. Useful for
quick questions ("Wie oft sollte ich als Anfänger laufen?") without going through the full
upload → preferences → plan-generation flow.

## Calendar & adjusting a plan

The "Kalender" tab lets you note upcoming events (races, travel, anything that affects
training) — both plan generation and plan adaptation send upcoming events to Claude as
context automatically.

In the "Plan" tab, once a plan exists you get three actions:
- **Plan anpassen** — adjusts the current plan in place (same weeks, revised going forward)
  given fresh training data, calendar events, and an optional free-text note about what
  changed (illness, injury, a moved race date, more/less available time).
- **Neuen Plan erstellen** — starts over from the preferences wizard.
- **Plan löschen** — clears the current plan back to the empty state.

## Personal bests, race predictions, and feedback

- **Persönliche Bestzeiten** (Dashboard): best known time near each standard distance
  (5K/10K/half/marathon), computed from uploaded activities within ±5% of the target distance
  (there's no GPS-split data to interpolate an exact-distance time from). You can also enter
  bests manually in the plan wizard — useful if you haven't uploaded anything yet; a manual
  entry always takes priority over an activity-derived one for the same distance, since it's
  you stating a fact (e.g. an untracked race) rather than an approximation.
- **Rennzeit-Prognose**: projected finish times extrapolated from your single best recent
  effort (last 90 days) using Riegel's race-time-prediction formula
  (`T2 = T1 * (D2/D1)^1.06`), a well-established public formula — not a Claude call, pure math.
- **Gefühls-Check-in**: tap 😞/😐/😄 on any non-rest day in the plan to log how it felt. Recent
  check-ins are sent to Claude as context when you click "Plan anpassen", so a run of hard/bad
  ratings nudges the next weeks toward easier training even without writing a note about it.
- **Krafttraining**: the plan can include a `strength` day type (short strength/mobility
  session) alongside the running day types, when it fits the schedule.

## How it works

1. **Upload** — GPX/TCX are parsed as XML, FIT is parsed as binary via `fit-file-parser`, CSV
   (Garmin's activity-list export) is parsed with `csv-parse`. Each file is normalized into a
   common shape (date, distance, duration, pace, heart rate, elevation) and deduplicated by
   date+distance+duration before being stored in SQLite.
2. **Aggregation** — before anything is sent to Claude, the stored activities are reduced to a
   compact summary (weekly mileage, pace trend, longest run, frequency, elevation trend, a
   recent hard-effort proxy). All the arithmetic happens in code — Claude never sees raw
   per-run data.
3. **Plan generation** — the aggregated summary + your preferences are sent to Claude
   (`claude-haiku-4-5-20251001` by default) with a strict JSON output schema (German weekday
   names, German plan text). If the response isn't valid JSON, it retries once with the parse
   error appended to the prompt. The resulting plan is cached in SQLite and only regenerated
   when you click "Plan neu erstellen".

## Notes

- Database file lives at `backend/data/app.db` (gitignored).
- Passwords are hashed with Node's built-in `crypto.scrypt` (salted, timing-safe compare) —
  no bcrypt/argon2 native dependency needed. Sessions are random tokens stored in a `sessions`
  table, sent as an httpOnly, secure, sameSite=lax cookie; there's no JWT/stateless auth, so a
  session can be revoked instantly (e.g. deleting its row) if needed.
- There's no CORS setup because there's nothing cross-origin to allow: the frontend and API
  are always same-origin (Vite's dev proxy locally, the same Express process in production).
- `better-sqlite3` was intentionally avoided — it requires a native build toolchain, which isn't
  guaranteed to be present (e.g. no Visual Studio Build Tools on Windows). Node's built-in
  `node:sqlite` gives the same synchronous API with zero native dependencies.
- GPX parsing is done directly with `fast-xml-parser` rather than the `gpxparser` npm package,
  because `gpxparser` installs a global `jsdom` shim as a side effect of being imported, which
  pollutes Node's global scope (`window`, `document`, `navigator`) and breaks unrelated code —
  in this app it caused the Anthropic SDK's browser-environment safety check to misfire.
- Preferences and the "day" field in generated plans use German weekday names (Montag..Sonntag)
  as their canonical values throughout — not just as a display label — since this is a
  single-language personal tool.
- PWA icons (`frontend/public/icons/`) are generated by `frontend/scripts/make-icons.cjs`, a
  small script that hand-encodes PNGs via Node's built-in `zlib` — no image library dependency.
  Re-run it with `node scripts/make-icons.cjs` if you want to tweak the icon design.
